# WISTELL-D plasma: baseline, attribution and the opt-in distance ceiling — pre-registration

Written October 9, 2026, after the baseline and profile below and before building v4.

## Facts established before this plan

* **Baseline (`plasma/runs/plasma-base-01`).** The retained transport-009 inputs ran unchanged on
  the control build (`9bf312f3…`). Both statepoints are bitwise identical to the retained
  September 26 `f301f7a7…` results (custom and builtin tally digests equal). Quiet-condition
  transport was custom 25.975 s and builtin ZTorus 0.130 s, a ratio of 200, against the 1.25
  gate.
* **Source occupancy confound (`plasma/source_occupancy.py`).** All 256 source sites are one
  point, (1209, 0, 0) cm. It lies inside the custom LCFS and outside the torus proxy. The custom
  model therefore starts every history inside 7.8 g/cm3 iron. Mean collisions (tally `total`)
  per source neutron are 68.40 for custom and 5.41 for builtin, a workload ratio of 12.6. The
  retained ratio of 159.7 (and 200 here) mixes this workload mismatch with geometry cost. At
  matched collision counts the custom model would be roughly 200 / 12.6 ≈ 16 times more costly
  per event. This is descriptive, not a fitted attribution.
* **Profile (`plasma/runs/plasma-prof-01`, 600 gdb samples, results bitwise unchanged).**
  * `SurfacePeriodicSpline::distance` accounts for 94.7% of samples.
  * `PeriodicRadialSurface::evaluate`, mostly the scan/bisection/golden-section steps of
    `solve_tangent_interval`, accounts for 54.5%.
  * The traversal body accounts for 17%, and Newton seed solves for 12%.
  * Spline coefficient indexing (`%` per control point) is 22% innermost, and `hypot`, `fmod`
    and `atan2` together about 10%.
  * Collision physics is about 2%.

## Change under test: patch v4, the opt-in distance ceiling

Files are in `patches/v4/`, generated by `apply_v4.py` from `*.orig`. The v4 build is
v2 + v3 + v4.

1. `Particle::event_advance` samples the collision distance before calling
   `distance_to_boundary`. The boundary search consumes no random numbers, so the random-number
   stream is unchanged.
2. Opt-in path (`OPENMC_STELLARCSG_DISTANCE_CEILING=1`; default off): a thread-local ceiling
   equal to that collision distance is set only around `distance_to_boundary`.
   `Region::distance` resets the ceiling to infinity for complex regions.
3. `SurfacePeriodicSpline::distance` behaves as follows when the query is not coincident and
   the ceiling is finite. It first asks
   `CompiledPeriodicSplineSurface::segment_clear_of_patches(r, u, c(1+1e-6) + 1e-3 cm)`.
   * The certificate traverses the existing patch BVH.
   * Boxes are padded by 1e-6 × characteristic length (1.5e-3 cm).
   * It returns true only if no padded patch box meets the ray segment.
   * If true, the surface returns INFTY. Otherwise the unchanged solver runs.

**Why results cannot change.** The general solver only returns roots inside patches it visits:
* Seeded roots lie within the projected tolerance (1e-10 cm) of a point inside the patch box.
* Interval roots lie inside the patch slab interval.

So after a true certificate the solver could only return a distance beyond the limit. At such
distances the particle collides in both versions, because the crossing test is
`collision > boundary`. The 1e-3 cm margin dominates every relative (1e-14) and absolute
(1e-12) tie tolerance in `distance_to_nearest_surface` and `distance_to_boundary`. With the
ceiling off, the only change is the order of two independent statements.

## Tests and decision

All tests use the same child limits, quiet admission and private lock. The shared lease is
untouched.

1. **Ceiling off (gate).** v4 reproduces the control digests bitwise for:
   * plasma custom and builtin (seed 1741);
   * P00 and ring (ladder-02 reference digests).
2. **Ceiling on (gate).** v4 reproduces the same digests bitwise for:
   * plasma custom and builtin, seeds 1741 and 1742 (1742 differs only in `<seed>`);
   * P00 and ring.
   P00 facets do not consume the ceiling in v4. This is a no-change control for the guard and
   the reordering.
3. **Timing.** 5 randomized blocks of {control, v4-on} × {custom, builtin}, order seed
   20261013.
   * S = median T(control, custom) / median T(v4-on, custom), with a min/max band.
   * The builtin is a negative control and must fall within [0.95, 1.05].
   * Report v4-on custom/builtin against 1.25.

Decision: if any bitwise gate fails, REJECT and preserve the evidence. Otherwise:

| Condition | Verdict |
|---|---|
| S_lo ≥ 2.0 | ACCEPT_SPEEDUP_EVIDENCE |
| S_hi < 2.0 | REJECT_EFFECT |
| otherwise | UNDECIDED |

Integration still requires independent review. The source-occupancy confound is reported
separately. It is a benchmark-design question for the project owner and is not changed here.

## Amendment 1 (written before building v5): ceiling for P00 facet surfaces

**Semantic note on v4 and v5.** With the ceiling on, a solver failure that would be thrown
(unresolved or ambiguous contact) is no longer raised when its location is certified to lie
beyond the sampled collision site. Without the ceiling such a failure aborts the run, even
though it cannot affect the history. No completed run in this campaign hit one.

**Patch v5** (`patches/v5/apply_v5.py`, v5 = v2 + v3 + v4 + v5). The same certificate is added
for `CompiledFacetSurfaceSet` as `segment_clear`:
* It traverses the existing triangle BVH.
* Triangle boxes are padded by 1e-6 × the coordinate scale.
* It skips the periodic caps that `distance()` also skips.

`SurfaceFacetSet::distance` returns INFTY when the certificate holds below
c(1+1e-6) + 1e-3 cm. `distance()` reports hits and ambiguities only inside visited triangle
boxes, so the exactness argument above carries over.

Tests (same rules):
1. **Bitwise gates, ceiling off and on.**
   * P00 and ring seed 1741 reproduce the ladder-02 references.
   * Plasma custom and builtin, seeds 1741 and 1742, reproduce the control digests.
   * In addition, with the ceiling on, the `xval_run.py` set reproduces its references: P00 and
     ring seed 1742, and P00 at k = 1/8, 1/4 and 1/2.
2. **gate-02.** This is the GATE_PLAN.md design with only the build changed: 3 seeds × {P00, ring}
   × 5 repeats on v5 with the ceiling on, order seed 20261014. The verdicts PASS_ROBUST /
   PASS_MEDIAN / FAIL are unchanged.

**Reading.** At matched workload the custom plasma costs about 76 µs per history in geometry,
against about 1 µs per collision all-in for the torus. Passing at 1.25 needs about a 3× cut in
that overhead. The remaining candidates are scan skipping beyond the current best root, a
cheaper residual than `hypot`, and in-solver ceiling pruning. Each can change which root is
returned in rare tie or grazing cases, through the solver's path-dependent acceptance and
deduplication. They therefore need validation against the independent oracle
(`STELLARCSG_VERIFY_FAST_WITH_ORACLE` / `distance_reference`), not bitwise identity. This
pre-registration stops here.

## Independent construction and coverage

`P00_STEP3_ORACLE_20261001.py` uses only the Python standard library. It
converts represented binary64 facet coordinates and the adapter-returned
normalized ray direction to exact `Fraction` values. For every triangle it
intersects the supporting plane, then tests the three oriented edge
half-spaces. Coplanar rays are clipped against affine inequalities to obtain
closed rational contact intervals. Every contact parameter and the entire
event ordering are exact. The implementation does not use candidate BVH
nodes, bounding boxes, or Moller-Trumbore predicates.

Tied first contacts are resolved only if they have one component and one
oriented plane normal. Creases, vertices, coplanar intervals, and unsupported
zero-distance first contacts remain ambiguous. A coincident hint removes
only a point contact at parameter zero when an exact unique local origin
face is independently established. A positive coplanar interval remains.

Float tolerances are confined to comparing returned distance and normal:
`2e-9 * max(1, abs(expected_distance))` and `2e-9` per unit-normal component.
The exact oracle certifies the returned binary64 ray, rather than an ideal
unrounded input direction. Exact rational event parameters are retained in
`P00_STEP3_EVENTS_20261001.jsonl`.

Cube cases cover entry, exit, miss, planar triangulation seam, coplanar
crease and vertex contacts, inward/outward coincident origins, no coincidence
hint, near seams/creases/origins, tangency, off-plane parallel rays, disjoint,
overlapping and touching components, later ambiguity versus an earlier
resolved event, earlier intervals versus later hits, reversed facet order,
all six face normals, seam normals, and unsupported crease/vertex normals.
Analytic slab distances and orthogonal normals provide the self-check oracle.
Corrupted distance, component, normal, hit presence, and false ambiguity
resolution are rejected by the comparison gate.

P00 cases cover 324 fixture-point axis rays, 144 face entry/exit rays,
72 near-edge rays, 72 vertex rays, 72 nearly parallel rays, 36 periodic-cap
probes, and 18 all-component competition rays. The retained fixture contains
3,348 triangles in 18 components and 108 points. Its solid-angle containment
test and baseline/candidate parity comparison are complementary evidence;
this event oracle does not derive its labels from their outputs.

## Exact counterexamples

Two closed cubes with component IDs 7 and 8 occupy `[0,1]^3` and
`[1,2] x [0,1]^2`, respectively. Their common face is `x=1`, with oriented
normals `(+1,0,0)` for component 7 and `(-1,0,0)` for component 8.

| Query ID | Origin | Direction | Coincident | Exact first parameter | Candidate result |
| --- | --- | --- | --- | --- | --- |
| 31 | `(1/4, binary64(0.31), binary64(0.42))` | `(1,0,0)` | false | `3/4` | component 7, normal `+x`, unresolved false |
| 36 | `(0, binary64(0.31), binary64(0.42))` | `(1,0,0)` | true | `1` | component 7, normal `+x`, unresolved false |
| 62 | same as 31; reversed facet order | `(1,0,0)` | false | `3/4` | component 8, normal `-x`, unresolved false |

For query 31 the exact event certificate contains component 7/facet 7 and
component 8/facet 16, both singleton intervals `[3/4,3/4]`, with opposing
normals. Query 36 has the same two contacts at `[1,1]` after its authorized
origin contact is removed. Query 62 preserves the geometric contact while
reversing input order. The candidate therefore returns a different component
and normal for the same geometric interface depending on facet order.

The probable implementation cause is the resolved-hit update conditioned on
`hit.t < best.distance` in `CompiledFacetSurfaceSet::distance`: an equal-time
clean hit from a conflicting component/normal does not establish ambiguity.
The rational certificates and reversed-order query substantiate the defect
without relying on that source-level explanation. A corrective change should
retain a terminal ambiguity for a conflicting simultaneous contact while
allowing same-component coplanar triangulation seams. Re-run this adapter
against a newly hash-bound executable after any implementation change.

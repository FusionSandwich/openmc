## Method and certified scope

`dev/stellarcsg/tests/P00_STEP3_ORACLE_20261001.py` uses only Python's standard
library. Decimal fixture tokens are first parsed to binary64 and then converted
to exact rational numbers with `Fraction(float(token))`. Thus the certificate
is for the actual represented coordinates, not the printed decimal rational
or an ideal CAD surface. The C++ driver exposes the production-normalized
binary64 direction; the oracle certifies that exact ray and its ordered events.

For each triangle, form its exact oriented normal `n=(b-a) cross (c-a)`.
Intersect the supporting plane by `t=-n dot (p-a)/(n dot d)`. Accept the point
only when all three oriented edge half-space inequalities are nonnegative.
When both plane gap and slope are zero, clip all three affine inequalities
against `t>=0` to obtain a closed interval. These intervals are retained in the
event ledger, including zero-length contacts and intervals beginning at the
origin. There is no BVH, AABB candidate exclusion, epsilon predicate, parity
ray, Moller-Trumbore determinant/barycentric routine, or production predicate
reuse in this oracle.

Exact event ordering groups equal first parameters. A positive point contact
is resolved only with one component, one positively proportional oriented
normal, and transverse direction. A nonzero interval, competing component,
crease/vertex, tangent point or unhinted origin contact is ambiguous. An exact
unique origin-face normal plus the coincident hint permits discarding only an
isolated zero contact, never the positive part of a coplanar interval.
`normal_at` expectations enumerate exact supporting facets; analytic cube
crease/vertex normals must remain absent. Normal vectors are compared after
normalization, with componentwise tolerance `2e-9`; physical-distance comparison
uses `2e-9*max(1,abs(expected_distance))`. Predicate decisions and first-event
ordering remain exact. These numerical output tolerances are verification
limits, not certified production error bounds.

Oracle self-checks use analytic cube slab entry/exit/miss distances, seam,
crease and vertex cases; verify the union of coplanar triangle intervals spans
`[1,2]`; check face/seam/crease/vertex/off-face normals; and reject corrupted
first distance, component, normal, hit presence and resolved ambiguity.
The initial interval self-check failed because it expected one triangle to
cover a whole triangulated face. It was corrected to check the exact interval
union; the failure is preserved, not silently overwritten.

## Decisive counterexamples

Take closed cubes with component 7 on `[0,1]^3` and component 8 on
`[1,2] x [0,1]^2`. For `p=(0.25,0.31,0.42)`, `d=(1,0,0)`, the exact first
parameter is `3/4`. Two simultaneous face interiors occur there:

| Final query | Model/input order | Candidate distance | Candidate component | Candidate normal | Candidate unresolved |
|---|---|---:|---:|---|---|
| 31 | cube 7 then cube 8 | 0.75 | 7 | `(1,0,0)` | false |
| 62 | cube 8 then cube 7 | 0.75 | 8 | `(-1,0,0)` | false |

Both exact ledgers contain the same first point event with component 7/+x
and component 8/-x. Reordering identical geometry changes the reported owner
and normal. Query 36, from `(0,0.31,0.42)` with inward direction and a valid
coincident hint, gives the same unresolved tie at parameter `1`, but production
resolves it as component 7/+x. These are positive-distance events, not an
origin-zero policy discrepancy or tolerance artifact.

Source explanation: the ordinary interior-hit branch updates only when
`hit.t < best.distance` and does not aggregate equal-distance ordinary hits.
Unique-normal checks are applied to ambiguous triangle-edge hits, so they do
not catch this shared face-interior tie. The counterexample challenges a
one-component/one-normal first-contact contract across closed components.
If an explicit component-priority policy is intended instead, it must define
and implement the tie result independently of facet/BVH input order. If the
representation is intended as a Boolean union, the shared internal face needs
an explicit union-navigation policy rather than an implicit triangle winner.

Production adapters that call separate single-component surfaces are not
automatically disproved by this aggregate-model case. The tested 738-query P00
subset has zero failed comparisons. The finding blocks a blanket claim that
arbitrary accepted multi-component facet sets provide unique, order-independent
first-hit owner and normal; its relevance to the actual P00 ownership path
requires root's independent scope review.

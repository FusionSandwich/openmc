## Question

The retained 100k P00/ring transport ratios (2.368216, 2.608274) compare models whose
material workloads differ: the corrected 20k pair has 3.99x the iron track length and
3.88x the collision rate in P00. Is the gap mainly geometry cost, or mainly workload?

* **H1 (workload-dominated):** at matched collisions per history, P00 transport is
  <= 1.25x the fixed-ring transport.
* **H2 (geometry-bound):** at matched collisions per history, P00 exceeds the ring by
  more than 1.5x.
* **Floor F:** the ring's own time at P00's declared collision workload relative to its
  nominal time. F > 1.25 means no geometry that is no cheaper per collision than the
  built-in rings could pass the gate on this proxy pairing.

This is a diagnostic. Changing density changes the declared physics; no result here is a
speed-gate acceptance.

## Allowed change

* Only the Fe56 `density value` in `materials.xml`, multiplier k:
  P00 k in {1/8, 1/4, 1/2, 1}; ring k in {1, 2, 4, 8}. All k are powers of two, so the
  written density is exactly k x 7.8 in binary64. k=1 uses the unmodified file.
* Counting runs only: append one zero-filter tally 303, score `events`, estimator
  `collision` (the retained diagnostic definition). Tallies consume no random numbers.
* Nothing else: no geometry, source, settings, binary, library or source-code change; no
  build; zero acquisition bytes.

## Schedule

1. Phase A, counting: one run per arm (8 runs), 100k histories, seed 1741.
2. Bracketing gate: P00 collisions-per-history range must contain the ring k=1 value and
   the ring range must contain the P00 k=1 value; counts strictly increase with k.
   Otherwise stop before timing (`LADDER_NOT_BRACKETED`).
3. Phase B, timing: 3 randomized complete blocks of the 8 arms (24 runs), production
   tallies only, seed 1741. Block orders are generated from seed 20261008 and sealed in
   `plan.json` before Phase A.

## Execution limits

Local only, Debian WSL, retained runtime. Shared lease
`local-coil-wave-20260926/compute.lock` acquired atomically by `mkdir`; an existing lease
means `COMPUTE_DEFERRED` (no polling, no reclamation). One child at a time, one thread,

(`/home/sman/workload-ladder-20261008/ladder-01`, no overwrite); evidence copied to
`runs/ladder-01/`. Stop at the first failure, no retry, no successor phase. Release the
lease only after the child has exited.

## Validity gates (any failure: INCONCLUSIVE, no decision)

* Every identity above matches; every child exits 0 with 100 complete batches and no
  `lost particle`, `unresolved` or `fatal error` output; all tally values finite.
* Replication: each k=1 timing run reproduces the retained seed-1741 production raw arrays
  (tallies 1-3, SUM and SUM_SQ) bitwise.
* Determinism and count binding: within an arm, all three timing runs and the counting run
  have bitwise-identical production arrays.
* Collision count integrity: `events = SUM(tally 303) x 1000` is within 1e-6 of an integer.
* Timing noise: coefficient of variation <= 5% in every arm.
* Drift: ring k=1 block times max/min - 1 <= 5%.
* Linear fit T = A + B C per model: max relative residual <= 5%.

## Decision quantities and rules

T = transport timer; C = collisions per history; per arm med/lo/hi = median/min/max of the
three repeats. Interpolate linearly in C between bracketing arms, separately for med, lo
and hi curves.

* F = T_ring(C_P00(1)) / T_ring(1); bounds use lo/hi curves against hi/lo denominators.
* R_thin = T_P00(C_ring(1)) / T_ring(1).
* R_dense = T_P00(1) / T_ring(C_P00(1)).

| Result | Decision |
|---|---|
| F_lo > 1.25 | Gate unreachable on this pairing for any geometry no cheaper per collision than the built-in rings: proxy specification blocks the goal. |
| R_thin_hi <= 1.25 and R_dense_hi <= 1.25 | WORKLOAD_DOMINATED: P00 geometry competitive at matched workload. |
| R_thin_lo > 1.5 and R_dense_lo > 1.5 | GEOMETRY_BOUND: fits A (per history) and B (per collision) locate the excess and set a numeric speedup target. |
| otherwise | MIXED: report, no decision. |

  the child, host processor time after the run. Telemetry is descriptive and never excludes
  a run from the gates.

If ladder-02 also fails the noise gates, the conclusion is that this shared machine cannot
support a 5% repeat CV for this workload; any change of estimator or gate would need a new

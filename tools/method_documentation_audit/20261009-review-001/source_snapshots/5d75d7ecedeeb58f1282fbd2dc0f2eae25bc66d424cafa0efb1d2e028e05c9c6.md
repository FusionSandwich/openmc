# Focused built-in-plane gap localization

The first plane run stopped at a 10-second client timeout after three 8–9-second successful clients. This bounded follow-up tests only the positive `2^-48` cm gap, both equivalent token orders and both retained matched libraries (eight rows, four clients). It uses the existing native executables, `OPENMC_CROSS_SECTIONS` file and no build, acquisition or production source edits.

Each client gets at most 15 seconds; the overall budget is 85 seconds. One Debian WSL thread and a 1 GiB virtual-memory cap remain in force. The output is a new unique directory under `dev/stellarcsg/reports`, under 1 MiB. The shared local compute lease must be absent and freshly acquired; the process removes only its own lease. A nonzero exit, missing row, or time cap makes the run incomplete and prevents a scientific pass claim. Preserve raw stdout/stderr, returned distances, accepted crossing, owner and scores.

The purpose is to locate whether the tiny-gap error occurs with OpenMC built-in planes, and whether token order changes it. It does not test the actual P00 mesh, higher precision, stochastic transport or publication acceptance.

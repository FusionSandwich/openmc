## Decision and prerequisites

Use **34 fixed uint64 counters per worker**, no timers, atomics, maps, per-cell
histograms, allocation interposer or per-query output. This is the smallest
proposed set for the distinctions below: two geometric traversal families, four
normal causes, region masking, committed ownership, and five tally dispatch
families. It is a work-frequency census, not a measurement of exclusive time,
scored bin writes, physical coil identity, or an absolute mathematical minimum
for every possible diagnostic question.

Implementation/build/transport must wait for the originating root to accept
the assembly-level first-event/normal/owner/scoring gate and supply explicit live
resource admission. The integration report documents that the combined-kernel
touching-cube failures neither prove nor disprove native P00 correctness:
`SurfaceFacetSet` filters the payload to one XML component per surface, whereas
the OpenMC region selects one surface token with its own tolerance. Counts
cannot resolve or certify simultaneous events. Keep the original facet fixture
and the seam-repaired transported HDF5 identity distinct.

Step 4 calls the counter receipt “Step 3”; the integration report calls the
independent event oracle “Step 3”. Use the role `geometry_work_census` and this
filename when handing off; do not replace the existing oracle receipts or imply
that this design satisfies the missing implemented counter dependency.

## Frozen v1 counter semantics

Each row below is one key unless it explicitly expands into four keys. Increment
by exactly one at the named operation, before its existing computation. Count
executed work, including rejection paths and repeats; never count theoretical
triangles, unique nodes, accepted hits, implied calls or RNG-weighted events.
Exception/abort paths may increment entry counts but cannot produce a complete
accepted census. All keys are whole-model totals within the transport epochs.
Facet keys cover only this facet kernel; OpenMC region/event/tally keys cover
their native whole-model paths. Different rows are not additive elapsed costs.

| Key(s) | Exact increment and meaning |
| --- | --- |
| `contains_calls` | Kernel contains entry, before finite validation. One per actual call, including adapter evaluate. |
| `contains_outer_aabb_tests` | Immediately before the existing expanded-box predicate, once per finite current-kernel contains. Six coordinate inequalities together are one test. The pre-AABB algorithm executes none. |
| `contains_outer_aabb_rejects` | Existing outer-box early-return-false branch taken. No independent predicate recomputation. |
| `contains_parity_rays` | Parity-ray entry, including later rays and rays that exit unresolved. |
| `contains_bvh_node_tests` | Immediately before each parity traversal node ray-interval call, including root and rejected nodes. |
| `contains_triangle_aabb_tests` | Immediately before each parity triangle-box ray-interval call. |
| `contains_triangle_intersections` | Immediately before each parity call to intersect-triangle that survives box rejection. |
| `distance_calls` | Kernel distance entry, before finite/nonzero validation. No separate adapter counter for the same delegation. |
| `distance_bvh_node_tests` | Immediately before each distance traversal node ray-interval call, including root and pruned nodes. |
| `distance_triangle_aabb_tests` | Immediately before each distance triangle-box ray-interval call; skipped caps do not contribute. |
| `distance_triangle_intersections` | Immediately before each distance intersect-triangle call surviving its box test. |
| `distance_periodic_cap_skips` | Existing cap-mask skip branch taken, once per encountered triangle, even if both cap bits satisfy the condition. Not all caps in the payload. |
| `normal_calls_{side,origin,seam,api}` (four keys) | Normal-at entry classified by immediate invocation cause: adapter evaluate's unresolved-side fallback; distance's coincident-origin confirmation; distance's ambiguous positive-hit seam recovery; any public normal-at/SurfaceFacetSet::normal invocation respectively. These are exclusive. |
| `normal_triangle_tests_{side,origin,seam,api}` (four keys) | Each normal-at loop iteration before its plane-gap computation, classified by the same invocation cause. Count only visited triangles before any early return. |
| `region_contains_calls` | Entry to contains-simple or contains-complex, never additionally at the public Region::contains wrapper. Includes distance-complex membership probes and repeated cell searches. |
| `region_distance_scans` | Entry to distance-to-nearest-surface, once per token scan; complex region virtual steps may generate many scans. |
| `region_masked_candidates` | In distance-complex, after its candidate normal and membership evaluation, the existing candidate fails to change membership and execution continues with on-surface updated. Excludes INFTY return and candidates that terminate the region search. |
| `boundary_queries` | Entry to global distance-to-boundary, once per requested boundary search, regardless of whether collision wins. |
| `boundary_events` | Entry to Particle::event-cross-surface, once per dispatched physical surface/lattice event. Virtual region candidates do not count. |
| `boundary_bc_dispatches` | Immediately before the existing surf.bc_->handle-particle call in Particle::cross-surface, only when the existing mode/BC condition permits dispatch. |
| `owner_changes_boundary` | At successful geometric completion of a boundary event, predecessor and successor owner keys differ. Definition and placement below. |
| `owner_changes_collision` | Successful near-surface collision reconciliation changes the predecessor owner key; sampled collision physics or temporary assignments alone do not count. |
| `collision_dispatches` | Once immediately before the existing collision or collision-mg call in event-collide; both share this key. Not function entry plus dispatch, collision tallies, or reaction counts. |
| `tally_tracklength_dispatches` | Entry to score-tracklength-tally; count actual wrapper calls, including zero-distance calls if executed. |
| `tally_collision_dispatches` | Entry to score-collision-tally. |
| `tally_analog_dispatches` | Entry to score-analog-tally-ce or -mg, one combined key. |
| `tally_surface_dispatches` | Entry to score-surface-tally, including any multiple calls generated by BC handling. |
| `tally_meshsurface_dispatches` | Entry to score-meshsurface-tally, including collision/BC/death callers. |

This expands to 7 contains + 5 distance + 8 normal + 3 region + 3 boundary +
2 owner + 1 collision + 5 tally = **34 keys, 272 counter bytes per worker**.
Add only a normal-cause byte and sticky failure/overflow flags. A 64-byte-aligned
record should fit 320 bytes on the admitted ABI; verify sizeof/alignof in the
later build receipt, rather than assuming an ABI size. No per-component arrays.

Normal cause is instrumentation-only TLS state, default `api`, set/restored by
a small no-throw scoped guard around the three internal call sites and the
adapter normal call. Normal-at reads it once per invocation for a local counter
selection. The guard must cover only the actual normal invocation: short-circuit
`coincident && ...` must remain short-circuited. No re-evaluation, extra normal
query, recomputed geometric comparison, changed floating expression or publicly
changed kernel signature. Ensure adapter and kernel use the same TLS definition
in one owning library; an inline TLS definition duplicated in an executable or
another DSO would silently split totals. Direct standalone normal-at calls use
`api`; that key does not claim to separate native region, sense, BC and scoring
callers. Native boundary/tally dispatch keys provide their separate path counts.

Owner v1 is **OpenMC cell ownership**, not physical coil ownership: key
`(lowest coordinate cell index, cell_instance)` on the validated one-level P00
geometry. Compare against a local snapshot made before boundary coordinate
levels change. Increment after cross-surface returns successfully, before
surface-source/weight-window/tally side effects; for a lattice event, after
cross-lattice returns successfully and before surface tally scoring. Require a
live, nonlost particle and a valid material-fill cell at geometric completion.
Vacuum termination supplies no successor and does not count. Reflection or
periodic transfer with the same owner does not count; a different successor does.
For collision, capture immediately before reconcile-cell-after-collision and
compare only after its successful return on the existing near-surface/alive path.
Count one committed transition, not assignments in failed neighbor searches,
birth-cell discovery, temporary surface-tally cell manipulation or secondary
initialization. A loss marks the epoch invalid even if tracking tolerates it.
These two counts are frequencies only; the assembly gate must retain actual
predecessor/successor identities and event certificates separately.

V1 admission requires fixed-source CE, one MPI rank, history mode with normal
secondary handling, n_coord=1/no lattice/distribcell ambiguity, ordinary CSG plus
the selected facet adapter, and the exact production/diagnostic XML in Step 4.
Reject unsupported geometry/modes before run sealing; do not silently reinterpret
the owner key for nested/transformed models. Timed-tracklength, pulse-height,
derivative, random-ray and accelerator tally paths are outside v1; confirm their
absence from the frozen settings/tallies. An observed unsupported path makes
export incomplete. Do not install or implement counters for unused subsystems.

## Compile-time removal, lifetime and export

Propose CMake option `OPENMC_P00_CENSUS`, default OFF, and a consistent target
definition `OPENMC_P00_CENSUS=1` when ON. OFF hook macros expand to `((void)0)`
and never evaluate their arguments. Guard all TLS declarations/definitions,
cause guards, owner snapshots/comparisons, collectors, exporter references and
added includes with the same preprocessor condition. No runtime enable flag,
counter accessor call, TLS access, branch, allocation or output remains OFF.
Require one macro setting across adapter/kernel/geometry/particle/tally units;
apply the definition to the owning library, not just the executable.

At the beginning of each normal history transport OpenMP region, each worker
zeros its TLS values, sets cause=api, and clears flags. Put reset before primary
track initialization so resampling/location work in that transport epoch counts.
At the end of that same region, before its worker leaves, copy TLS to a unique
preallocated `(epoch, worker)` slot; record participation/completion once. Slots
are allocated before transport; hot hooks never allocate. After the region join,
the controller reduces snapshots with checked integer addition. Reset again at
the next epoch. This excludes cold model construction, XML/payload loading,
out-of-epoch geometry probes and statepoint-writing work. It includes births and
secondary transport occurring inside the normal history loop. The counters'
epoch interval need not cover every activity included in OpenMC's broader
transport timer: report both scopes exactly.

For v1 only one worker is admitted, but the design must retain actual worker
participation and epoch counts. Do not harvest TLS with a new parallel region or
a static/TLS destructor, assume omp-thread ID implies stable TLS, or reduce into
a shared integer per increment. Future multithread/MPI support requires its own
coverage/reduction review; no unchecked MPI_SUM of uint64 totals.

Per hook use unsigned increment with sticky overflow detection (e.g. increment
then, if it became zero, set overflow). Counter wrapping is defined for uint64,
but its wrapped value is invalid evidence. All bulk adds/reductions use checked
addition; never clear an overflow flag mid-epoch or after aggregation. Do not
throw from a hook/destructor or alter physics on overflow: invalidate export,
retain diagnostics and reject the census. Exercise wrap deliberately near MAX
in later tests; practical small counts are not an overflow proof.

After all expected epochs finish, native successful completion and statepoint
closure, the controller writes one bounded sidecar via exclusive temporary file
and atomic final rename in a new output directory. No overwrite of prior output.
Record schema `P00_GEOMETRY_WORK_CENSUS_V1`, run-id/seed, schema SHA256,
`complete`, `overflow`, actual mode/thread/rank/epoch coverage, failure flags,
binary/library pins and plan SHA256. `values` has exactly the 34 required keys
with exact JSON integers, not doubles or strings. Final output is O(34), not
O(events); retain snapshots only for the bounded verification receipt if needed.
Writer/export/participation failure, lost particle, unsupported path, exception,
timeout, nonzero worker exit or overflow implies `complete=false` (or absent
final file). Never write a complete sidecar in a crash handler or destructor.

The schema must state per-key applicability. A supported path that executed
zero operations is zero. `contains_outer_aabb_*` is zero for pre-AABB because
that algorithm lacks this operation, explicitly labeled `algorithm_absent`;
its hook coverage is still reviewed. An empty analog/surface tally list gives
zero dispatches, labeled `configured_inactive`. Unimplemented/unsupported
coverage is UNKNOWN and blocks sealing, never a numeric zero. OFF runs have no
counter sidecar and must not be represented by a 34-zero ON result.

Step 4's current checker validates exact keys, integer bounds, complete=true and
schema identity, but does not explicitly validate an overflow/coverage manifest.
Root should require and independently review that validation before sealing a
real plan (or pin a separately reviewed export validator). A producer's
complete=true assertion alone does not prove worker participation. This report
does not edit the checker or assert its existing booleans prove these semantics.

## Build identity and verification plan after admission

1. **Preserve and pin sources.** Rehash the files below and freeze a source
   snapshot plus instrumentation patch and schema. Apply the same counters to
   the retained pre-AABB algorithm and current algorithm. Within each pair,
   ON/OFF differ only by the census build definition/its required generated
   build metadata; do not combine profiler flags, debug builds or geometry fixes.
   Pre/current still differ by the accepted AABB optimization (and corresponding
   AABB hooks). Ring-OFF uses the exact current-OFF executable/library.
2. **Obtain resource admission first.** Before any build, even zero-download
   compilation, record current RAM, drive free space, significant processes,
   available tool/runtime versions/environments/caches/checkouts, sufficiency,
   acquisition bytes, output target and rollback, then the root's bounded
   live resource receipt/shared lease. Use existing local capabilities. This
   design supplies neither inventory nor execution authorization.
3. **Removal proof.** Compare a pristine algorithm OFF build to the same
   instrumented source OFF build with identical compiler, flags, strict FP,
   optimization/LTO/dependencies and reproducible path metadata. Inspect
   preprocessed hot units and disassembly of contains/parity/distance/normal,
   region, boundary/event and tally call paths. Require no census TLS accesses,
   calls, branches, symbols or argument evaluation and equivalent hot machine
   instructions/control flow after normalizing address/debug metadata. Review
   inline callers and linked library, not just one out-of-line function. A
   stripped executable or macro-off source alone is insufficient evidence.
4. **Mechanical exact controls.** With tiny hand-audited meshes, test far outside
   (current AABB test=reject=1, parity work=0; pre AABB=0 with real parity work),
   interior/exterior near the box (one to three actual parity entries), direct
   normal linear scans and early conflict, coincident true/false short-circuit,
   seam recovery and cap skips before box tests. Independently enumerate actual
   BVH visits/box calls/intersections for the chosen tiny fixture. Assert no
   doubled shared-helper counts; a rejected root node is still one node test.
5. **Native layer controls.** Use root-accepted assembly cases to check complex
   region masked candidates versus physical boundary dispatch, crossing to a
   different priority cell with unchanged material, reflection/periodic same
   owner, terminal vacuum, and successful collision reconciliation. Births and
   unsuccessful tentative cell assignments must not increment owner changes.
   Assert tally wrappers execute once with known active lists and repeated
   BC surface scores count multiple dispatches. Never infer collision count
   from a weighted events tally. Pin exact event transcripts and raw bins.
6. **Export adversarial controls.** Exercise two successive epochs and reset,
   worker-slot completeness, intentional uint64 wrap and aggregate overflow,
   wrong schema/run/seed, missing/extra keys, Boolean/float counts, lost particle,
   unsupported mode, incomplete/duplicate snapshot, absent final output and
   failed rename. Each rejects. A synthetic two-worker collection test can
   verify TLS isolation/reduction under separate bounded admission; it does not
   change Step 4's one-thread limit or qualify parallel transport numerics.
7. **Identity receipt.** Pin source hashes, patch/schema/exporter/checker hashes,
   complete CMake cache, normalized compile/link commands, compiler/linker and
   dependency versions/hashes, strict-FP settings, target-wide macro coverage,
   OFF-removal disassembly receipt, binary/library hashes and actual loader
   path. Distinct isolated build directories for pre-OFF/pre-ON/current-OFF/
   current-ON; preserve the original runtime/evidence. SHA hashes of ON/OFF may
   differ and do not by themselves establish comparable builds.
8. **Bounded matrix and overhead.** Only after root acceptance, use the sealed
   Step 4 eighteen-run, three-seed matrix and its one sequential worker limits.
   Require exact paired raw SUM/SUM_SQ/local bins and accepted event semantics.
   Compare current diagnostic ON/OFF with identical XML/seed/runtime provenance:
   per-seed overhead = ON transport seconds / OFF transport seconds - 1;
   median >5% rejects counters for timing attribution. Keep output/export wall
   time separate and require export completion even though it is outside the
   transport timer. OFF production timers alone evaluate geometry speed.
   No pre-ON/OFF overhead claim follows: this matrix measures current overhead
   only. No new runs or automatic repetitions are part of this design.

Useful checks for complete valid runs: outer rejects <= outer tests <= contains
calls; current outer tests = contains calls; pre outer tests=rejects=0;
contains parity rays <= 3*(contains calls - outer rejects); each triangle
intersection count <= its family's triangle-box count. Normal triangle tests
are separate linear work and must not be added to ray intersections as identical
operations. Masked candidates <= region distance scans. BC dispatches <= boundary
events in this admitted path. Owner-change counts need not match material changes,
triangle hits or surface events. Count differences cannot certify trajectory
equality; exact event/bin tests remain mandatory. No percentage of transport
time, Amdahl fraction or claimed 47–52% removable share follows from counts.

## Behavior

An ON census now requires every admitted worker epoch, each bound to the run,
seed and plan; exact integer primary coverage; explicit successful completion;
and explicit absence of overflow. Python checked reduction rejects totals at
or above 2^64 before comparing them with the reported run totals. A missing,
duplicate, stale, incomplete or overflowing worker cannot pass because its
aggregate values look plausible. `threads=true` is also rejected as an invalid
terminal worker count. Numerical/bin/filter/loader/input gates, the 18-run
matrix, OFF behavior, timing comparisons and exit-code meanings are retained.

Legacy aggregate-only ON outputs are intentionally rejected; old retained
receipts are preserved as historical evidence, not rewritten or retroactively
claimed to satisfy the new contract. A future producer and plan must use the
schema below. The original Step 4 protocol's minimal counter-output paragraph
is insufficient for this revised checker. Root must review/pin this contract
and changed checker before sealing any native plan; no such plan is created here.

## Exact accepted counter contract

The pinned counter-schema JSON requires:

```json
{
  "schema": "P00_GEOMETRY_WORK_CENSUS_V1",
  "required_keys": ["<reviewed counter name>", "<another name>"],
  "coverage": {
    "batches": 20,
    "generations_per_batch": 1,
    "mpi_ranks": 1,
    "workers_per_rank": 1,
    "primaries_per_epoch": 1000
  }
}
```

`required_keys` must be a nonempty list of unique nonempty strings (maximum
128). The eventual 34 native keys still require independent instrumentation
review; the synthetic fixture uses two artificial keys. Additional schema
documentation fields are permitted; coverage has exactly the five fields above,
with actual integers. Other modes/topologies are unsupported and reject.

The counter-output JSON has **exactly** these top-level fields:
`schema`, `run_id`, `seed`, `plan_sha256`, `schema_sha256`, `complete`, `overflow`,
`values`, `worker_epochs`. Schema matches the name above; run/seed/plan/schema
hash match the pinned matrix identities. Seed is an integer, complete is true,
overflow is false; integer 1/0 are not accepted for those flags. Runtime/library
identity remains checked through the existing terminal/outcome artifacts rather
than additional counter-sidecar fields.

`values` is a dictionary with exactly the schema's required keys and actual JSON
integer values in [0, 2^64). Boolean, float, string, negative, missing, additional
or out-of-range values reject. Zero is valid work absence, never a substitute for
missing coverage. An OFF run has no counter_output artifact under the existing
outcome schema.

`worker_epochs` is exactly 20 dictionaries. Each dictionary has **exactly**:
`run_id`, `seed`, `plan_sha256`, `batch`, `generation`, `rank`, `worker`,
`complete`, `overflow`, `primaries`, `values`. Run/seed/plan match individually;
seed and all four epoch identity coordinates are actual integers. Expected
identity set is `(batch=1..20, generation=1, rank=0, worker=0)`, each exactly once.
Order is immaterial. Every snapshot requires complete=true, overflow=false,
primaries=1000 and the same strictly validated counter keys/value domain.
Run values must equal the checked sum of all snapshots, key by key. A worker
wrap flag rejects even with ordinary in-range values and a complete run flag.

This checker **rejects reported per-worker overflow** and detects aggregation
overflow. It cannot reconstruct a wrap the producer failed to flag, prove that
hooks cover all work, or certify worker counters against native execution.
Native checked-increment/TLS/export receipts and the assembly correctness gate
remain necessary. Producer must invalidate completion on loss, unsupported
paths, timeout/abort or failed export, and root must independently verify that
contract; existing native terminal/HDF/log gates also remain active.

PYTHONDONTWRITEBYTECODE=1 and only synthesized local HDF/XML/JSON/text artifacts
inside the new `P00_COUNTER_CHECKER_20261001_01` report directory.

- Final `selftest-02.stdout.json`: full positive synthetic 18-run matrix passes;
  **65 negative controls reject** (29 retained controls, one strict terminal
  worker-type control, 35 counter coverage/schema controls). Exact uint64 MAX,
  zero counts and reordered complete epochs pass. Exit 0, stderr empty.
- Meaningful counterexamples: duplicate epoch with unchanged aggregate; worker
  incomplete while run says complete; stale per-worker run/seed/plan; wrong
  batch/generation/rank/worker; missing/extra worker; flagged wrap with in-range
  values; all local values valid but sum wraps uint64; invalid count types;
  partial primaries; wrong totals; unsupported/missing schema coverage.
  New controls assert rejection reason, so a stale pin or unrelated failure
  cannot make them pass accidentally.
- `cli_receipt.json`: five complete CLI audits against pinned synthetic plans:
  positive exit 0; incomplete worker, worker overflow, duplicate epoch and

  Changed counter outputs were independently re-pinned in new outcome files;
  earlier fixtures were left intact.
- Initial `selftest.stdout.json` retains the 64-control passing run before the
  Boolean-terminal-thread case was added. It is not the final receipt.

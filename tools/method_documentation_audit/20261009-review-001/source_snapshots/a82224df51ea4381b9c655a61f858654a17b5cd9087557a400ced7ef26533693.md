## Source-level mechanism for this row

At the selected B exit, the binary64 event position is `x=1.0000000000000036`. Its signed distance to A's right plane is exactly `2^-48`, nonzero. `Particle::event_cross_surface()` forwards the selected B surface to `cross_surface()`, which calls `neighbor_list_find_cell()` and then `Cell::contains` through `find_cell_inner()` (`src/particle.cpp:332,656,705`; `src/geometry.cpp:127,281`). `Region::contains_simple()` uses the selected surface as an override only for its own token; the separate A token calls `Surface::sense()` (`src/cell.cpp:1046–1064`). `Surface::sense()` treats **any** `abs(f) < FP_COINCIDENT` as coincident and takes the outgoing direction's dot product with the normal (`src/surface.cpp:123–135`); here `FP_COINCIDENT=1e-12` (`include/openmc/constants.h:55`), so A is classified inside even though the represented event point is still strictly outside A. This code path explains the observed B→A jump. The independent distance reducer's relative `FP_PRECISION=1e-14` can produce a separate first-contact selection error under other token orders (`src/cell.cpp:962–993`).

This is a trace of the code's decisions for the observed row, not a validated repair. Lowering a tolerance globally could change true-coincident behavior and still leave unrepresentable intermediate states and scoring unresolved.
